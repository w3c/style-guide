# W3C Style Guide

This is the README file for the W3C Style Guide during the external review (beta), lasting from Monday, 19 October 2026 to Friday, 29 January 2027.

## Introduction and purpose

The W3C Style Guide unifies guidance previously spread across multiple internal style guides and editorial resources, as well as guidance adapted from established conventions used in major US style manuals, such as Modern Language Association (MLA) style and The Chicago Manual of Style. It also documents W3C-specific conventions, including terminology, tone, voice, and editorial preferences. 

The guide aims to promote readability, consistency, and easier translation across W3C content, which spans standards-related materials, educational resources, organizational communications, and website content.

It empowers W3C writers, editors, and contributors across W3C to write content serving a global audience.

## Motivations and benefits

* Improved consistency across W3C publications and websites  
* Reduced ambiguity when making editorial decisions  
* Fewer recurring discussions about style and terminology  
* More efficient onboarding of contributors and editors  
* A clearer path for maintaining and evolving editorial guidance over time

## Maintenance

The maintenance of the W3C Style Guide will continue to be collaborative and follow the living document approach using GitHub issues and pull requests.

## Phased review

The W3C Team expects a phased review period lasting between August 2026 and March 2027.

### Project scope and approach

The draft W3C Style Guide was created in July 2026 as a single, consistent editorial reference for W3C authors, with the aim of reducing duplication across W3C guidance documents. 

This was done by comparing the [WAI Style Guide](https://wai-website-theme.netlify.app/style-guide/one-page/), the [W3C Manual of Style](https://www.w3.org/guide/manual-of-style/) that’s currently in effect for W3C authors, and older W3C editorial guidance. 

The goal was to identify guidance applicable to all W3C authors and to move specialized guidance into companion documents that can be linked to from the new W3C Style Guide. 

We deliberately chose wording that is easier to apply, reduces ambiguity, follows authoritative US style guidance, and aligns with W3C’s evolving editorial practices, which increasingly prioritize user experience.

This work has resulted in the separation of the W3C Manual of Style into two documents:

* (unified) W3C Style Guide (this document)   
* (draft) [W3C Specification Editor Handbook](https://pr-preview.s3.amazonaws.com/w3c/guide/pull/445.html)

### Exiting final review (March 2027\)

Actions to take before exiting the review period and shifting to regular maintenance mode:

* Obsolete existing information in the old style guides   
* Ask the Internationalization team to update “Editorial guidelines for i18n docs” (that is, to leave only guidance specific to i18n docs, and to point to the W3C Style Guide): [https\://www\.w3.org/International/i18n-activity/guidelines/editing](https://www.w3.org/International/i18n-activity/guidelines/editing)   
* Apply W3C Style Guide guidance to the [W3C Process Document](https://www.w3.org/policies/process/) (and other major published documents)

### Areas for future improvement

We considered the following items to be out of scope for the initial work but identified them as worthwhile future improvements to the style guide:

* Add a section to the Guide that provides an orientation to W3C guides and companion documents  
* Provide a full table of contents, ideally sticky in the sidebar, that highlights the current heading as the reader moves through the document
